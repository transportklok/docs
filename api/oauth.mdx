## Hoe het werkt

TransportKlok gebruikt OAuth 2.0 met de authorization code flow. Uw app stuurt de gebruiker naar TransportKlok. Daar logt de gebruiker in, kiest de organisaties en geeft toestemming. Uw app wisselt daarna een code in voor een toegangstoken en een refresh token.

## Een client aanvragen

Een OAuth-client vraagt u aan bij TransportKlok via [info@transportklok.nl](mailto:info@transportklok.nl). Geef op:

- de naam, een beschrijving, een logo en de website van uw app;
- de redirect-URL's waar TransportKlok de gebruiker na het toestaan naartoe stuurt;
- de scopes die uw app nodig heeft;
- of uw app voor beheerders of voor medewerkers is.

U krijgt een client-id en, voor een app met een eigen server, een client secret.

## De stappen

1. Stuur de gebruiker naar het autorisatieadres:

   ```text
   https://app.transportklok.nl/oauth/authorize
     ?client_id=<client-id>
     &redirect_uri=<redirect-url>
     &response_type=code
     &scope=<scopes, met spaties ertussen>
     &state=<willekeurige waarde>
   ```

2. De gebruiker ziet **Applicatie autoriseren**, kiest bij **Toegestane organisaties** de organisaties en klikt op **Toestaan**.
3. TransportKlok stuurt de gebruiker terug naar uw redirect-URL met `code` en `state`. Controleer dat `state` gelijk is aan wat u meestuurde.
4. Wissel de code in voor een token:

   ```http
   POST /oauth/token HTTP/1.1
   Host: app.transportklok.nl
   Content-Type: application/x-www-form-urlencoded

   grant_type=authorization_code&client_id=<client-id>&client_secret=<client-secret>&redirect_uri=<redirect-url>&code=<code>
   ```

5. Het antwoord bevat `access_token`, `refresh_token`, `token_type` en `expires_in` (in seconden).

## Een nieuw token ophalen

Is het toegangstoken verlopen, vraag dan met het refresh token een nieuw aan:

```http
POST /oauth/token HTTP/1.1
Host: app.transportklok.nl
Content-Type: application/x-www-form-urlencoded

grant_type=refresh_token&client_id=<client-id>&client_secret=<client-secret>&refresh_token=<refresh-token>
```

## Wat de gebruiker ziet

Wat de gebruiker bij het toestaan ziet en hoe die de toegang weer intrekt, staat bij [Een app toegang geven](/sign-in/app-access).
